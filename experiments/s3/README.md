# S3 warm validators

This standalone Rust experiment measures real ripgrep, ItsDangerous and Zod gates, not checkout-only fanout. It does not implement the rewrite or select shipping defaults. The [qualification report](../../docs/spikes/s3/README.md) maps observations and pending acceptance.

Run from the repository root with Git, Rust/rustfmt, Node/npm, uv and Bash available. Windows uses native Rust, Git for Windows and Git Bash, not WSL. Fixture roots must use a local drive: canonical extended-length drive paths are normalized before generating external command arguments and environment values; UNC and device roots are rejected. Unix paths retain their original characters. Host tools are recorded rather than silently replaced. If uv is absent, the wrapper installs the pinned uv 0.6.17 wheel with the runner Python into the experiment build directory; its pip cache also stays there. The experiment installs exactly Yarn 1.22.22 inside its disposable root; Zod's pinned revision uses `yarn.lock`, so no package-manager conversion is made. uv creates a Python 3.12 environment and uses the fixture's pinned test requirements plus flit_core 3.9.0. The patch version of Python and host tool versions remain provenance inputs, not fully hermetic pins.

```sh
bash experiments/s3/run.sh .throwaway/s3-new-run
bash experiments/s3/collect.sh .throwaway/s3-new-run .throwaway/s3-new-evidence
```

Both root and adjacent `.build` must be new. All repositories, downloads, native dependency caches and builds live under `.throwaway/`. Rust gate tests alone use a fresh private OS temporary directory per slot outside Git ancestry, because the pinned ripgrep suite tests non-repository ignore behavior. The directory is logged and removed after gate work; cleanup errors fail completed Rust runs, with best-effort cleanup on early errors. Forced harness termination can leave it behind. Set `S3_TEMP_PARENT` to an existing non-repository directory if the OS temporary parent has a `.git` ancestor; this is an explicit exception to worktree-local temporary state, not a changed or skipped upstream test. Every subprocess records its command, working directory, duration, exit status and output. Fixture commit/tree identities are captured by Git. Wrappers record harness SHA-256, toolchain and host provenance. Collection only includes top-level generated `.log`, timing TSV and source-hash files; it never traverses dependency source trees. Collection remains useful after failures, and failures preserve nonzero status.

Each ecosystem records fresh dependency bootstrap, the first gate (cold compilation where applicable), five raw warm-cache gates, five switches to harmless but distinct tracked-source candidates plus their gates, and bootstrap-input invalidation. The metric is `(median(warm switch + gate) - median(raw gate)) / median(raw gate)`, independently compared to the unchanged strict `<0.15` bound. The pinned Rust binary source is `crates/core/main.rs`; fixture manifest/source paths must be tracked before measurements begin. A failed gate aborts that ecosystem without declaring a latency pass; subsequent ecosystems still run. Each command has a five-minute timeout and kills its process group/tree. The shared workflow's fifteen-minute job timeout remains a separate hard bound and may interrupt collection.

After measurement, invalidation changes a bootstrap input, compares all declared bootstrap input bytes, and reruns bootstrap. A deliberately invalid source file must fail the real native gate with existing caches. Ignored and untracked residue are removed with `git clean` only inside disposable fixtures, retaining named dependency environments. Two separately bootstrapped slots then execute real gates concurrently with independent temp/build/cache directories, `MAI_SLOT` and `MAI_PORT_BASE=0` (ephemeral cooperative allocation). Two subprocess fixtures read the slot/port environment and demonstrate a genuine bind collision and retry on distinct ephemeral ports. Environment variables are cooperation, not sandboxing; uncooperative repository commands can escape them.

A worker spawns a heartbeat descendant. Cancellation uses Unix process groups or native Windows `taskkill /T /F`, reaps the parent, and verifies that the descendant heartbeat stops. This is a cooperative descendant fixture, not proof that adversarial detached processes cannot survive. Linux/macOS probe `cp --reflink=always` / `cp -c`; all platforms verify ordinary-copy independence. Windows COW capability probing is explicitly pending and safe copy is the fallback. No overlay or lazy materializer is introduced.

The manual-only [workflow](../../.github/workflows/experiment-s3.yml) reuses the existing evidence runner, platform selection, fifteen-minute limit and thirty-day artifact retention. It must first be registered on the default branch. No workflow is dispatched by this change. Native macOS/Windows execution remains pending manual evidence collection.

## Functional versus performance results

Under [historical ADR 0010](https://github.com/maida-ai/mai/blob/9ee6acc844acc3e8272ebd24d8301c6b4af6870c/docs/adr/0010-staged-mvp-qualification.md), the wrapper defaults to `S3_MODE=functional`. Explicit `S3_MODE=run` retains the original strict <15% performance exit criterion. `S3_MODE=functional bash experiments/s3/run.sh .throwaway/s3-functional` executes the same gates, samples, invalidation and isolation checks but reports performance separately. Both modes preserve `criterion_lt_0.15=false` for a missed target. Functional failures always exit nonzero; functional mode does not imply a performance GO. `summary.log` records mode, functional failures, performance completeness and failed performance ecosystems. Native Windows/macOS verification of the correction still requires fresh manual CI; no old artifact is rewritten.
