# S6 lockfile regeneration experiment

This standalone Rust harness tests the proposed regeneration boundary using real Git, Cargo, npm and uv processes. It does not import or implement mai product code. [Qualification report](../../docs/spikes/s6/README.md) maps the issue criteria to evidence and limitations.

From the repository root, with Rust, Git, Node/npm and Python 3.10+ available:

```sh
bash experiments/s6/run.sh .throwaway/s6-new-run
bash experiments/s6/collect.sh .throwaway/s6-new-run .throwaway/s6-new-evidence
```

The output and adjacent `.build` path must be new and under `.throwaway/`. The wrapper uses an installed uv, recording its version, or bootstraps exactly `uv==0.12.18` into a disposable Python virtual environment. This fixture tool bootstrap uses that environment's pip and an isolated download cache, never the user's Python installation. It requires package-index access only when uv is missing; fixture regeneration and gates are offline. Cargo, npm, Rust, Node and Python use the host versions recorded in evidence. No production dependency is added. Git Bash with native Rust/Python/Node is required on Windows; WSL is not native Windows evidence.

Each ecosystem has two local, source-pinned dependency fixtures, alpha and beta version 1.0.0, returning 11 and 22. Their source is generated deterministically from the hashed harness and wheel backend. Cargo builds path crates, npm installs local packages, and uv builds and installs actual wheels using a tiny dependency-free PEP 517 backend. These are deliberately small synthetic fixtures, not representative public registry packages. npm's additions use separate dependencies and optionalDependencies sections to exercise nonoverlapping manifest edits; its gate explicitly requires both modules, so an optional installation failure cannot pass.

Each agent branch independently changes its manifest and generates its own lockfile. Separate manifest-only commits retain their common baseline, and Git merges them with ordinary three-way semantics. The candidate starts with the byte-identical baseline lockfile, never either agent's generated lock. The validator regenerates twice from that baseline and requires identical output; the gate imports/executes both dependencies. A commit-tree publication and new-ref CAS assert the accepted tree and parent match successful evidence. This is an experiment protocol, not a production landing implementation.

The harness rejects pre-regeneration trees, changed parents and attempts; it compares protected configuration and executable script blobs against the trusted baseline. Each candidate replacement is rejected before executing its bytes. Native manager failures and injected failing gates are required negative results. A separately spawned worker is forcibly terminated after 100 ms to test timeout classification. Unix uses a process group and Windows uses taskkill /T /F; this probe has no grandchildren and does not establish complete process-tree cleanup or actual hung-resolver behavior.

The impossible-version cases mean dependency failures **under the explicit offline fixture inputs**, not general solver contradictions. Cargo rejects a mismatching local version, npm rejects an unavailable exact registry version with an empty isolated cache, and uv rejects an unavailable exact registry version after removing its local-source override. Additional incompatible-constraint fixtures make beta require alpha 2.0.0 while the root installs alpha 1.0.0 (`npm --strict-peer-deps --install-links`, requiring terminal ERESOLVE), and make beta require Python >=4 while the uv project supports Python >=3.10 (requiring No solution found). uv intentionally overrides declared registry versions when a local source is provided: the original negative fixture incorrectly assumed otherwise and failed. That discovery is retained in the report, not counted as an ecosystem failure.

Every external command records its arguments, working directory, outcome, duration and timeout. Evidence records versions, source hashes, Git tree/parent/config identities, attempts and limitations. `collect.sh` only copies an explicit allowlist of top-level logs and hashes; it never traverses repositories, virtual environments or package caches. Existing outputs are never removed automatically. Partial logs can be collected after failure.

The manual-only `experiment-s6.yml` workflow uses the existing shared runner, explicit linux/macos/windows/all selection, 15-minute job timeout and 30-day artifact retention. The dispatch workflow must first be registered on the default branch. This task does not dispatch it. Reviewed 2026-10-15 native CI passes on Linux, macOS and Windows; the report recommends GO for the scoped three-ecosystem fixture issue. A hosted job passing these fixtures would not by itself qualify registry behavior or realistic dependency graphs. Shipping example defaults remain a maintainer decision.

The final verification also pins both uv fixture build backends to baseline Git blobs, rejects their replacement, and snapshots the candidate tracked tree before the gate and verifies it is unchanged afterward. Separate npm/uv offline-unavailable failures are not claimed as unsatisfiable solver constraints. Additional fixtures require npm ERESOLVE for an exact incompatible alpha peer and uv No solution found for beta requiring Python >=4 against the project supporting >=3.10.
