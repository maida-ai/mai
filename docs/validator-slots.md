# Native processes and validator slots

The reusable `process` and `slots` Rust modules provide bounded execution for trusted local services. They do not enable receive, landing, scheduling or an integration queue, and validator slots are not OS sandboxes. Candidate code executes with the service account's filesystem and network privileges; deliberately escaping Unix process groups or attacking service metadata is outside this isolation boundary.

`RunSpec` explicitly supplies the executable, arguments, working directory, environment overrides, timeout and per-stream output-tail byte capacity. Both streams are drained concurrently, retaining only their final configured bytes. Invalid UTF-8 is rendered with replacement characters, so rendered text can contain up to three times that byte count. The maximum configured tail is 16 MiB per stream. Results distinguish success, nonzero failure, timeout, cancellation and cleanup failure, and include exit status when available and elapsed milliseconds. Spawn/configuration errors return an error. Inherited `GIT_*` variables are removed before explicit overrides are applied, preventing accidental repository/configuration redirection.

Unix commands run in their own process group. A separate session watchdog holds a close-on-exec owner lifeline, receives the candidate process-group identity before exec, and kills that group if the owner disappears. A readiness check prevents a terminal/process-group termination from killing the watchdog alongside its owner. Windows uses a kill-on-close Job Object assigned atomically through `CreateProcessW`'s Job List attribute; Windows 10 or later is required and failure to establish the job fails closed. Bare Windows executables resolve against the service's PATH before switching to candidate cwd. Batch programs (`.cmd` and `.bat`) are rejected; configure an explicit native interpreter executable and declare its script dependencies instead. Explicit `cmd.exe` commands require `/D /S /C` followed by exactly one script argument (switch casing is ignored). That final script retains its original UTF-16, embedded quotes and shell metacharacters; the runner adds only the outer quote pair consumed by `/S`. Other cmd argument forms reject with guidance instead of applying CRT escaping to shell syntax. Ordinary native executable arguments use CRT quoting only when needed, preserving simple switches literally.

Normal completion also terminates remaining descendants. Cleanup waits at most one additional second for process/output completion and group/job quiescence. Linux treats zombies as terminated because they cannot execute or retain resources; other Unix systems require the process group to disappear. An escaped process retaining an output pipe cannot make an output-reader join wait forever: the result becomes cleanup failure and the slot remains unavailable. Native Windows and macOS runtime qualification belongs to native CI; a cross-platform type check alone does not establish runtime support.

`SlotSettings` requires a positive slot count, port base, ports per slot and explicit cache directory list. Each pool allocates disjoint port ranges and supplies `MAI_SLOT`, `MAI_PORT_BASE`, `TMPDIR`, `TMP` and `TEMP`. Port ranges are allocation hints within this pool, not reservations against other services or pools. Every occupied slot receives its own private system temporary directory outside any ancestor `.git` marker. Set the service's temporary-directory environment appropriately when system temporary roots contain repository markers; local sandbox verification used `TMPDIR=/var/tmp` because `/tmp/.git` exists there.

Slots contain ordinary independent clones with no alternates or shared writable environments. Materialization requires an exact full commit identity and verifies the fetched identity. Before each candidate, all files and Git metadata are recreated except explicitly configured cache directories. This removes ignored/untracked residue and poisoned Git configuration, hooks, attributes or sparse-checkout settings. Git control operations use the same bounded process runner with a 60-second safety timeout and 64 KiB diagnostic tails; global/system configuration and replacement refs are disabled. Cache paths are relative, cannot overlap `.git`, each other or tracked candidate content, and cannot traverse symlinks. Cache names are literal native paths, never Git-clean exclusion globs. Bootstrap callers must invalidate bootstrap evidence when required outputs were removed and must not treat retained caches as proof that a candidate passed.

Every lease has both an exclusive OS lock and a persistent occupied marker. Explicit `release` first removes candidate residue and private temporary files, then removes the claim. Dropping a lease, failed materialization, failed cleanup or abrupt owner death leaves the claim present, including across a service restart; unlocked locks and stale PIDs never authorize automatic reuse. These are process-interruption guarantees, not a claim of power-loss persistence for directory entries. An administrator must inspect retained diagnostics, terminate any residual processes, preserve relevant evidence and clean the engine-owned slot before removing an interrupted claim. There is deliberately no automatic stale-owner recovery command in this batch.
